## Investigated 2026-08-14 -- 34 of 36 bytes; two findings, loop shape open

The Zero Hour body is right. Two things about it are BFME's, and both are
worth having on their own:

**The TeamMemberList head is at Team+0x0c.** Team.cpp's
`getFirstItemIn_TeamMemberList()` lands it at +0x10.

**Object::setTeam is VIRTUAL, at vtable slot 20.** Retail loads the object's
vtable and calls `[eax+0x50]`; ZH declares `Object::setTeam` an ordinary
member and this tree emits a direct call to
`?setTeam@Object@@QAEXPAVTeam@@@Z`. Anything else in the tree that calls
setTeam directly is emitting the wrong instruction.

With both corrected the body comes out right except the loop shape. Retail
tests at the top and jumps back unconditionally:

```
loop:  mov  ecx,[esi+0x0c]
       test ecx,ecx
       je   end
       mov  eax,[ecx]
       push edi
       call DWORD PTR [eax+0x50]
       jmp  loop            ; eb f1
end:
```

Every spelling tried gets rotated by MSVC into a test-at-bottom loop that
re-reads the head after the call, two bytes longer:
`while ((obj = head) != 0)`, `for(;;) { obj = head; if (!obj) break; ... }`,
and `while (head) { head->setTeam(...); }` (that last one is worse again --
it reloads the head twice per iteration).

So the residual is loop rotation under /O2, not the reconstruction. Whoever
picks this up should look for a way to suppress rotation for one loop, or
check whether retail's compiland used a different /O setting -- the same
question packet 00933a50 is left on. Nothing was landed.
