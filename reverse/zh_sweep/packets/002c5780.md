## Investigated 2026-08-14 -- three offsets found, switch arity open

Compiled from SupplyTruckAIUpdate.cpp the body comes out the right shape.
Three offsets differ, and all three are worth having:

    StateMachine::m_currentState   +0x1c   this tree +0x20
    State::m_id                    +0x04   this tree +0x08

The first two are new. Note they sit alongside the three that
?ownerDocking@SupplyTruckStateMachine@@SA_NPAVState@@PAX@Z (converted,
0x002C5BB0) pins: State::m_machine +0x1c, StateMachine::m_owner +0x10,
Object::m_ai +0x204.

**What is open is the switch arity.** Retail guards the jump table with
`cmp eax,5 / ja`, so it dispatches six case values, 0 through 5. The ZH
source switches on five -- ST_IDLE, ST_BUSY, ST_REGROUPING, ST_WANTING,
ST_DOCKING -- and compiles to `cmp eax,4`. BFME's supply-truck state enum
has one more member than ZH's, and nothing in this body says which it is or
where in the order it sits.

The jump table at 0x006C57A4 answers it, but this packet's disassembly stops
partway through it and mis-decodes what it does show. The visible entries are
0x006C57A0 (the `xor al,al` return) and 0x006C579D (the `mov al,1` return);
reading all six in order gives the true/false answer per case, which with the
ZH names pins the new member's position.

Not landed: adding a sixth case without that table would be inventing an enum
member.

## LANDED 2026-08-15 (Open-BFME5) -- the jump table answers the arity

Read the six entries at RVA 0x002C57A4 out of the baseline image (the packet's
own disassembly mis-decodes them as instructions):

    case 0  -> 0x006C57A0   false
    case 1  -> 0x006C57A0   false
    case 2  -> 0x006C579D   TRUE
    case 3  -> 0x006C57A0   false
    case 4  -> 0x006C579D   TRUE
    case 5  -> 0x006C579D   TRUE
    (0xCCCCCCCC follows, so six is the whole table)

Zero Hour's enum is ST_IDLE 0, ST_BUSY 1, ST_WANTING 2, ST_REGROUPING 3,
ST_DOCKING 4, and its body returns false for ST_IDLE/ST_BUSY/ST_REGROUPING --
that is false at 0, 1 and 3, exactly what BFME does. So the five Zero Hour
names keep their Zero Hour values and **BFME's extra state is appended at index
5**, on the ferrying side. That was the open question.

Two more things the body needed:

- The row is **56 bytes, not 35**: the jump table is part of it.
- `StateMachine::getCurrentStateID()` must keep its null arm --
  `m_currentState ? m_currentState->getID() : INVALID_STATE_ID`. Retail tests
  m_currentState and branches straight to the switch's default, because 999999
  is outside the case range and MSVC folds the constant through the ternary.
  Dropping the arm costs four bytes and moves the first difference to +0x05.

Layout used, all confirmed by the byte match: AIUpdateInterface is 0x330 wide,
SupplyTruckAIInterface is the second base at object+0x330,
m_supplyTruckStateMachine is object+0x334, StateMachine::m_currentState +0x1c,
State::m_id +0x04.
