## Investigated 2026-08-13 -- reference class is provably WRONG

`??0GhostObjectManager@@QAE@XZ` is **already matched**, at 0x001B3AA0, **20
bytes**, from GhostObject.cpp -- a constructor that zeroes three members and
does nothing else. This body is 29 bytes, calls the Snapshot constructor copy
at 0x007E86B0 first, and stores a vtable at this+0. One class cannot produce
both: the matched one has no base and no vtable.

WHY THE 89.7% IS MISLEADING, and this is a whole family, not one packet:
"call the Snapshot constructor, zero N dwords, store the vtable, return this"
is the compiler's output for EVERY Snapshot subclass with N scalar members.
The vtable address is the only operand that could tell them apart, and it is
a relocation -- masked from the comparison. Worse, it does not discriminate
even when you read it by hand: this body stores 0x011296B0, and so does
0x00808880, so those two vtables are COMDAT-folded.

**N is the only discriminator these bodies carry.** Here N is 3.

Landed nearby on exactly that basis, with the limitation recorded in the
source: 0x00808880 as ??0Energy@@QAE@XZ, on N=4 matching ZH's
Energy::Energy. Treat any other member of this family the same way -- check
first whether the candidate name is already claimed at another address, then
accept that N and the packet score are all you have.

Open question for whoever picks this up: which Snapshot subclass has three
word-sized members? Note it cannot be one whose ZH declaration uses Bool for
the first two, since retail writes three full dwords at +0x04, +0x08, +0x0c.
