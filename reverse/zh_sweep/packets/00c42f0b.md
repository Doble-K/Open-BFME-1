Bulk sweep over all remaining packets flagged this one by shape, and the
disassembly in this packet confirms it: 4 `mov ecx,DWORD PTR [ebp-0xNN]` loads
feeding 3 `jmp` instructions to destructor addresses (0x1642d, 0x1db6f), with no prologue, no
epilogue and no single coherent control flow. Some blocks carry a null-check
(`cmp DWORD PTR [ebp-0xNN],0x0` / `je`) before computing a sub-object offset --
that is the compiler's conditional-cleanup shape, not user code.

This is compiler-generated per-member cleanup on an exception path. No portable
C++ body exists here; reproducing the bytes would require inventing member
layout to force a match, which the rules forbid.

- a chain of `mov ecx,[ebp-N]; jmp <dtor>` groups

  unrelated classes and therefore carry no class identity
