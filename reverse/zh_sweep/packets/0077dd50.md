## Investigated 2026-08-14 -- name already claimed elsewhere, at a different size

`??0CaveContainModuleData@@QAE@XZ` is **already matched**, at 0x00227200, **398 bytes**. This body is
**28**. One constructor cannot be both, and the size gap is far too large for
a boundary quibble.

This is the module-data constructor form of the false positive packets
007e87f0 and 00626060 document: "call the base constructor, store the vtable,
initialise N members" is the same shape for every module data class, the
vtable operand is a relocation and masked from the comparison, and the
similarity metric therefore cannot separate them. What little signal there is
lives in N and in the element offsets.

Before landing anything here, check whether the candidate name is already
claimed at another address -- that single check refutes it outright, and it
is cheaper than any byte work.
